# Meeting-Ops self-host installation

This is the installation detail behind the README quickstart. The supported
stranger path is Docker Compose on Linux; the old appliance script and local
GPU/model workflow are not part of this path.

## Requirements

- Linux with Docker Engine and Docker Compose v2
- `curl` and `openssl` on the host
- At least 8 GB of RAM and enough disk for the application images and database

The default stack does not require a GPU, NPU, Node.js, Python on the host,
Qdrant, LiteLLM, or a hosted identity provider.

## Installation

Run the README commands from a fresh checkout:

```bash
./install-meeting-ops.sh
```

The script:

1. checks Docker, Compose, `curl`, and `openssl`;
2. creates `.env` with random Postgres, Redis, and JWT signing secrets;
3. creates a random bootstrap admin username and policy-compliant password;
4. builds the API and web images and starts Postgres, Redis, API, and web;
5. initializes a fresh schema and waits for `http://127.0.0.1:9050/health`;
6. creates the verified local superuser inside the API container; and
7. prints the generated admin credentials.

The generated `.env` is ignored by Git and is chmod `0600`. It contains local
credentials and must stay on the host. Do not paste it into an issue, log,
commit, or support request.

## Identity and agent access

The self-host path uses the app's local email/password identity. It does not
depend on an external realm. The generated admin can sign in at
<http://127.0.0.1:7777/#/login> or through `POST /api/auth/login`.

Once the admin has an access token, create an agent PAT with:

```bash
curl -fsS -X POST http://127.0.0.1:9050/api/auth/pats \
  -H 'Authorization: Bearer REMOVED' \
  -H 'Content-Type: application/json' \
  -d '{"name":"my-agent","scope":"user","expires_in_days":90}'
```

The response contains a one-time `plaintext` value with the `mops_pat_`
prefix. Store that value in the agent's secret store. Do not put it in the
repository or a shell history. The PAT authenticates the REST API and the
hosted MCP endpoint at `http://127.0.0.1:9050/mcp`.

## Configuration

The compose file is `docker-compose.selfhost.yml`. It only binds services to
loopback by default. The supported local configuration names include:

- `APP_BASE_URL`, `APP_PUBLIC_URL`, and `CORS_ORIGINS` for the local web origin;
- `MEETING_OPS_API_PORT`, `MEETING_OPS_WEB_PORT`,
  `MEETING_OPS_POSTGRES_PORT`, and `MEETING_OPS_REDIS_PORT` for host ports;
- `LITELLM_API_BASE`, `LITELLM_API_KEY`, and `LLM_MODEL_*` for an optional
  OpenAI-compatible completion gateway;
- `INFINITY_ENDPOINT` for optional embeddings/reranking;
- `PARAKEET_SERVER_URL`, `SPEAKER_SVC_URL`, and `KOKORO_ENDPOINT` for optional
  server-side speech providers; and
- `MCP_HOSTED_ENABLED` when the local hosted MCP surface should be disabled.

After changing `.env`, apply it with:

```bash
docker compose --env-file .env -f docker-compose.selfhost.yml up -d
```

No provider or integration credential is generated by the repository. Supply
those values only through the host's secret-management process.

## Health and lifecycle

```bash
curl -fsS http://127.0.0.1:9050/health
docker compose --env-file .env -f docker-compose.selfhost.yml ps
docker compose --env-file .env -f docker-compose.selfhost.yml logs backend
docker compose --env-file .env -f docker-compose.selfhost.yml down
```

The `/health` URL reports API/router health and is the acceptance probe. The
deeper `/health/ready` probe includes optional providers and may be degraded
until those providers are configured.

`down` preserves the named Postgres and Redis volumes. `down -v` is destructive
to this local installation and is not part of the quickstart.

## Network boundary

The default compose publishes API, web, Postgres, and Redis only on
`127.0.0.1`. If an operator later places the web/API behind a TLS reverse
proxy, they must set the public URL and CORS variables for that deployment,
keep Postgres/Redis private, and use a separate secret-management system.
