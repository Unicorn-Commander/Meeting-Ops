### `064_backfill_legacy_weekly_digest_email` (`d1c64fa`)

What it changes. For each organization whose `settings.weekly_digest.enabled` is true, it selects members and turns `users.email_weekly_digest` on when the user's email is in `weekly_digest.recipients`, or, if that list is empty, when the membership role is `admin` or `manager` (`064_backfill_legacy_weekly_digest_email.py:24-45`).

Existing rows. Yes. One `UPDATE` on `users`. No insert, no delete, no change to `recording_sessions`. Organizations that are not enabled are skipped. Users who do not match stay at the `063` default, false (`063_in_app_digests.py:13-14`).

Reversible. No. `downgrade()` is `pass` with the comment "Do not turn off a user's explicit post-migration opt-in" (`064:48-50`). Rolling the image back does not clear the flag.

Runtime on ~913 sessions. The revision does not read or write `recording_sessions`. Cost is one scan of `organizations.settings`, a membership join per org that has weekly digest enabled, and one `UPDATE ... WHERE id IN (...)`. That is not proportional to the 913 sessions. This lane did not execute it. Dogfood has already applied it.

How it will run. `meet-backend` uses `backend/Dockerfile` `ENTRYPOINT` `backend/docker-entrypoint.sh`, which runs `alembic upgrade head` before uvicorn (`docker-entrypoint.sh:13-14`). The workers replace that entrypoint with arq (`docker-compose.unicorncommander.yml:361` and `:466`), so they do not migrate. `064` adds no column. `063`, already applied, added `email_weekly_digest`. A worker booting beside the migration does not need a new column. The data change still happens on the first new `meet-backend` start.
